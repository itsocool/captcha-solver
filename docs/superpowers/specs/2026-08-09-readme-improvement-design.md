# README 개선 설계

## 목표

`README.md`를 처음 설치하는 사용자, 모델 개발자, 운영·배포 담당자가 함께 사용할 수 있는 실무 진입 문서로 재구성한다. 현재 코드와 다른 설명을 바로잡고, 세부 구현 분석은 기존 전문 문서로 연결해 README의 탐색성을 높인다.

## 범위

- `README.md`의 정보 구조와 내용을 전면 정리한다.
- Python 학습/추론, FastAPI, Rust ONNX CLI, Spring Boot ONNX 서버의 관계를 설명한다.
- 실제 명령, 데이터/모델 규칙, REST API 계약, 환경 설정, 검증 명령을 제공한다.
- 코드, API, 설정 파일, 모델 파일은 변경하지 않는다.
- 새로운 아키텍처 결정이나 ADR은 만들지 않는다.

## 대상 독자

1. 프로젝트를 처음 설치하고 예측을 실행하려는 사용자
2. CAPTCHA 데이터를 추가하거나 CRNN을 재학습하려는 모델 개발자
3. FastAPI 또는 Spring Boot 서비스를 배포·운영하려는 담당자

각 독자는 상단의 실행 방식 비교표에서 자신의 경로를 선택하고, 필요한 독립 섹션으로 바로 이동할 수 있어야 한다.

## 콘텐츠 원칙

- 첫 화면에서 프로젝트의 목적과 네 실행 경로를 알 수 있게 한다.
- 명령은 현재 저장소에서 그대로 실행 가능한 형태로 제공한다.
- 구현 세부는 필요한 만큼만 설명하고 CRNN 내부 구조는 `docs/crnn_ctc.md`, 전체 기술 분석은 `docs/codebase-analysis.md`로 연결한다.
- 현재 코드와 충돌하는 설명은 코드 기준으로 수정한다. CNN 시간축은 `W/4`, 학습 증강은 현재 `core.py` 값을 사용한다.
- Python이 학습과 PyTorch 추론의 기준이며 Rust/Java는 동기화된 ONNX와 sidecar를 소비한다는 아티팩트 경계를 분명히 한다.
- 알려진 `.pt`와 JIT/ONNX 가중치 불일치 가능성, 감지 크기와 모델 크기 혼용, 파일 재분배의 파괴성을 숨기지 않는다.

## 오류 및 운영 정보

- FastAPI의 400/500 응답 조건과 `degraded` health 상태를 요약한다.
- DB 서비스 설정이 환경 변수보다 우선하며 변경 후 재시작이 필요함을 설명한다.
- 모델 캐시는 프로세스별이므로 다중 worker에서 모델 메모리가 복제됨을 경고한다.
- JSON base64 요청과 multipart 요청 예제를 모두 제공한다.

## 검증 기준

- README의 모든 내부 상대 링크가 존재한다.
- Python 빠른 시작 및 CTC 자체 점검 명령이 성공한다.
- Rust/Spring 명령은 각 하위 프로젝트의 실제 manifest와 README에 맞는다.
- 지원 CAPTCHA 설정, API 경로, 환경 변수, 이미지/모델 경로가 코드와 일치한다.
- `W/16`, “Python 평면 모듈만 존재”, “테스트 없음” 같은 오래된 설명이 남지 않는다.
- Markdown placeholder와 trailing whitespace가 없고 Mermaid 블록이 유효한 문법 구조를 갖는다.

## 비목표

- README에 모든 클래스와 함수의 상세 명세 복제
- 벤치마크 수치 갱신 또는 새 성능 측정
- Rust/Spring 배포 패키지 변경
